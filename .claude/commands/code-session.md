argument-hint: TASK 번호 (예: TASK-001)
---

너는 지금 **코드 세션**이다. 대상 작업: $ARGUMENTS

1. `docs/tasks/`에서 $ARGUMENTS 파일과 관련 설계 문서를 읽는다. 테스트 세션의 커밋과 테스트 파일을 확인한다.
2. **테스트 파일은 고치지 않는다.** 테스트가 틀렸다고 생각되면 고치지 말고 이유를 적어 승현에게 묻는다.
3. 작은 단위로: 테스트 하나(또는 한 묶음)를 통과시키고 → 실행 → 커밋 (`feat:`).
4. 문서에 없는 규칙을 코드에 추가하지 않는다.
5. 전부 통과하면: 돌연변이 테스트(서버는 mutmut)를 돌려 점수를 기록하고, 살아남은 돌연변이 목록을 보여 준다.
6. PR 설명 초안: 무엇을·왜, AC 결과 표, 돌연변이 점수, 막혔던 것(에러 원문·가설·확인한 것).
7. 승현이 실행해야 할 명령이 있으면 한 줄씩 무엇을 하는지 설명한다.
