# ADR-015 · 장소 데이터 출처: Google Places 기본 + 직접 고른 목록 + Serper는 두 자리에만

| 항목 | 내용 |
|---|---|
| 상태 | **승인** — 결정권자 2026-11-09 · **v1.1** 11-09: 영업시간 디스크 캐시 → 메모리 1시간, 표기 "Google Maps"(디자이너 지적) |
| 관련 | ADR-012 §3-3(출처 정책, 이 ADR이 일본 도시의 **출처 우선순위 1번**을 바꾼다) · ADR-014(Google 지도) · DATA-001 B(places·place_facts) · PORTFOLIO D-23(첫 도시 오사카) · TASK-010 |

## 1. 문제
첫 도시가 오사카(가설)로 정해졌다. 지금까지 화면은 가상 도시(`demo_city`)로 만들었다. 실제 여행을 만들려면 **오사카 장소의 이름·좌표·영업시간**이 필요하다. ADR-012는 한국 기준(TourAPI·카카오·네이버)이었고 "구글 정보는 Serper로 먼저 시험"이라고 적었다.

## 2. 선택지
| 안 | 장점 | 단점 |
|---|---|---|
| A. 손으로 정리 (공식 사이트를 보고 직접 입력) | 저장 제한 없음, 비용 0 | 50~80곳 손작업, 영업시간이 바뀌어도 모름 |
| **B. Google Places API (공식)** | 일본 데이터 충실, 지도(ADR-014)와 같은 출처, `place_id`로 길 안내 연결 | **저장 제한**(아래 §3-2), 호출 비용 |
| C. OpenStreetMap | 저장 자유 | 일본 가게 영업시간이 비어 있는 곳이 많음 (가설) |
| D. Serper (Google 검색 결과 API) | 이미 크레딧 있음, 검색 결과의 시각 값 | 검색 결과를 긁어 재판매하는 방식. Google이 2025-12 같은 방식의 SerpApi를 "보안 장치 우회"로 제소 |

## 3. 결정
**B를 기본으로 하고, 우리가 만든 값과 사용자 확인으로 채운다. D는 두 자리에만 쓴다.**

### 3-1. 값마다 출처를 나눈다
| 값 | 출처 | 저장 |
|---|---|---|
| 장소 목록(오사카 50~80곳), 한국어 이름, 별칭, 지역(난바·신사이바시·우메다) | **우리가 고름** (`osaka-seed`) | 저장소(git)에 |
| 카테고리 8종, 머무는 시간 범위, 혼잡·가격 단계, 분위기 태그 | **우리가 정함** | 저장소에 |
| `place_id` | Google (무기한 저장 허용) | 저장소에 |
| 좌표 | Google | 캐시만 (30일 안, git 밖) |
| 영업시간, 공식 사이트 | Google | **디스크에 저장하지 않음**. 필요할 때 불러 메모리에만 최대 1시간 (§3-2) |
| 지도 링크 | 우리가 `place_id`로 만듦 | 저장 가능 |
| Google에 영업시간이 없을 때 | **Serper** (만들 때 한 번) | 뽑은 **사실 값만** 캐시(git 밖), `unverified` (ADR-012 §3-3 사실 항목 수집) |
| 현장에서 본 사실 | 사용자 (TASK-008 T-05) | `user`, `confirmed` |

### 3-2. Google 약관에 맞춘 규칙
- 무기한 저장은 `place_id`와 **우리가 만든 값**만. Google 응답 원본은 저장소에 넣지 않는다 (테스트 데이터도 **손으로 만든 가짜**)
- 좌표는 30일 안에 다시 불러온다
- 영업시간 등 다른 값은 약관상 저장 예외가 없다 → **필요할 때 불러오고 디스크에 남기지 않는다** (11-09 결정권자: 비용은 크레딧으로 감당, 값도 늘 최신). 같은 계획 세션·같은 화면 안에서만 메모리로 다시 쓴다(최대 1시간, 가설)
- 부르는 때: 계획 세션 시작(그날 후보), 여행 중 화면(오늘 장소, 1시간에 한 번), **닫힘 대안 찾기(T-06, 근처 후보를 그 자리에서 — 대안이 "지금 열려 있는지"는 최신 값이어야 한다)**
- 표기: **"Google Maps"를 번역하지 않는다**. 지도 없이 Google 값을 보여 주는 곳(계획 후보 카드, 검색 결과)은 **Google 로고 필수**(공식 파일, 16~19dp). 공간이 좁으면 글자 "Google Maps"(Roboto 400, #5E5E5E 등, 대비 4.5 이상)
- 필드 마스크로 필요한 필드만 부른다. 비용은 크레딧으로 감당 (결정권자, 창업동아리 지원). 그래도 **호출 상한**을 둔다 (ADR-012 §4-3)

### 3-3. Serper는 두 자리에만 (결정권자 11-09)
| # | 쓰는 자리 | 규칙 |
|---|---|---|
| 1 | **개발 중 조사**: 오사카 후보 찾기, 폐업 여부, 공식 사이트 찾기 | 사람(PM·결정권자)이 목록을 만들 때 참고만. 앱·저장소에 결과를 남기지 않는다 |
| 2 | **빈 영업시간 보완** | 도시 데이터를 **만들 때 한 번** 호출. 검색 결과 문장에서 **시각 값만** 규칙으로 뽑고, 문장은 저장하지 않는다. 상태는 항상 `unverified`, 출처는 링크만 |
- **하지 않는 것**: 앱 사용자 요청마다 실시간 호출(⚠️ 재판매 구조, 출시 전 판단), 검색 요약 글·리뷰 저장이나 표시(❌ 저작권)

### 3-4. 보완을 더 붙일지는 재고 정한다
- TASK-010에서 목록 전체를 불러온 뒤 **카테고리별 영업시간 채움 비율**을 잰다 (Google만 / Google + Serper)
- 식당(food)이 **90%(가설)** 아래면 공식 API **Hot Pepper Gourmet**(리크루트, 출처 표시 필요, 조건 확인 전)을 R2에 검토한다
- **결과 (11-09, TASK-010 §13)**: 58곳 중 Google만 84.5%, + Serper 86.2%, **식당 100%** → Hot Pepper는 붙이지 않는다. 빈 곳은 거리·공원·밤거리(영업시간 개념이 약함) → 우리가 정한 값(`open_space`·`curated_hours`)으로 처리

### 3-5. 출처 표시 이름 (TASK-009 B3 확장)
| `source_type` | 화면 |
|---|---|
| `google` | Google Maps (번역 금지) |
| `serper` | 검색 결과 · 미확인 |
| `user` | 내가 확인 |
| `curated` | Tripfriends (우리가 정한 값: 머무는 시간 등) |
| `demo` | 데모 데이터 |
| 그 밖 | 출처 정보 |

## 4. 결과
- (+) 일본 데이터 품질과 지도·길 안내 연결이 한 출처로 맞는다
- (+) 서비스만의 값(목록·머무는 시간·분위기)은 우리 것이라 저장 제한이 없다
- (−) 영업시간을 그때그때 부르므로 호출이 늘고 응답이 느려질 수 있다 → 여러 곳을 **동시에** 부르고 시간 상한, 실패하면 `unknown`/`unverified` (TASK-010 §11)
- (−) 키 두 개(`GOOGLE_PLACES_API_KEY`, `SERPER_API_KEY`)는 `apps/server/.env`에만. 지도 키(ADR-014, 앱)와 따로 만든다
- ADR-012 §3-3 출처 우선순위 1번의 "Serper로 먼저 시험, 부족하면 Places" → 일본 도시는 **Places 먼저, Serper는 §3-3 두 자리**로 바뀐다

## 포트폴리오 포인트
- 값마다 "누구 것인가"를 나눠 저장 설계를 정함: 우리가 만든 값은 git에, 남의 값은 캐시에, 사용자가 본 값은 가장 믿을 수 있게
- 이미 있는 크레딧(Serper)을 무작정 쓰지 않고 쓰는 자리를 둘로 좁힘 → 법적 위험을 알고 감수한 범위를 문서로 남김
- 보완 출처를 미리 붙이지 않고 **채움 비율을 재고** 정함

| 예상 면접 질문 | 답 |
|---|---|
| "장소 데이터는 어디서 가져왔나요?" | Google Places 공식 API. 다만 약관상 무기한 저장은 `place_id`뿐이라, 목록·머무는 시간·분위기는 직접 만들어 저장하고 좌표는 30일 캐시, 영업시간은 필요할 때 불러 디스크에 남기지 않았다 |
| "검색 결과 API는 왜 제한했나요?" | 검색 결과를 긁는 방식이라 Google이 같은 업체를 제소했다. 개발 중 조사와 빈 영업시간 보완에만 쓰고, 값만 뽑아 '미확인'으로 표시했다 |
| "데이터가 틀리면요?" | 출처·확인 시각·상태를 함께 저장하고, 미확인이면 방문 전에 영업 확인 카드를 띄운다. 사용자가 확인한 값이 가장 높은 신뢰 |
