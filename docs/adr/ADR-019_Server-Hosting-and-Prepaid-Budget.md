# ADR-019 · 서버 호스팅: Google Cloud Run(0대 시작) + 선불로 활동 기간 뒤에도 돌아가게

| 항목 | 내용 |
|---|---|
| 상태 | **승인** — 결정권자 11-16 (호스팅·0대 시작·예산 배분). 결제는 결정권자가 직접 |
| 관련 | ADR-013(앱 + Python 서버 구조) · ADR-016(Supabase 익명 우선 계정) · ADR-017(비용 상한) · ADR-018(수집·평가 에이전트, LLM·Serper 비용) · TASK-012(Supabase) · TASK-013(CI) |

## 1. 문제
- 지금 서버는 노트북에서 `fastapi dev`로 켠다 → 파일럿(실제 사용자)엔 인터넷에서 계속 돌아가는 서버가 필요하다
- **돈의 조건**: 학교 환급 예산(남은 금액 약 35만 원)으로 결제. **창업동아리 활동 기간이 끝나면 다음 달부터 결제를 못 한다** → 월 구독·후불 카드는 활동 기간 뒤 서버를 멈추게 한다. **지금 한 번 넣어 두고 쓰는 만큼 빠지는 선불**이어야 한다
- 확장 가능성도 남기고 싶다 (지역을 일본에 묶지 않음)

## 2. 선택지 (공식 문서 확인 11-16)
"앱만 올리면 알아서 돌려 주는 곳(PaaS)" 중 많이 쓰는 곳

| 안 | 선불 | 확장·지역 | 판단 |
|---|---|---|---|
| **A. Google Cloud Run** | ✅ 선결제(보통 최소 $10), 남은 돈은 다음 청구에서 먼저 빠짐 | 요청 따라 자동 증감, **0대까지 줄어듦**. 도쿄(1등급)·서울(2등급) 등 | **채택** |
| B. Fly.io | ✅ $25부터 크레딧 | 좋음, 도쿄 | 차선 |
| C. DigitalOcean App Platform | ✅ 계정 선결제($50~, 등급별) | 가장 가까운 곳 싱가포르 | 대안 |
| D. Railway | ❌ 문서: 선불 불가, 후불 카드 | — | 탈락 (월 구독) |
| E. Render | ❌ 문서엔 프로모 크레딧만 | — | 탈락 |
| F. Heroku | ❌ 신용카드 후불 | — | 탈락 |
| G. Vercel | ❌ 월 구독, 프론트엔드용(오래 걸리는 LangGraph 요청에 안 맞음) | — | 탈락 |
| H. AWS App Runner 등 | ❌ 후불 카드가 기본 | 최고 | 탈락 (선불 조건) |
- VPS(Vultr·DigitalOcean Droplet)도 선불이 되지만 보안 업데이트·재시작을 직접 해야 해서 제외

## 3. 결정
1. **Google Cloud Run, 도쿄(asia-northeast1)**. 이유
   - 선불 + 0대까지 줄어 파일럿 규모면 **서버비가 무료 사용량 안**(가설)
   - **지도·Places API와 같은 Google Cloud 결제 계정** → 선결제 한 덩어리로 서버와 지도 비용이 같이 빠진다 (지도 API는 서버 위치와 상관없이 원래 이 계정에서 빠짐 — Cloud Run만의 기능은 아님, 관리 한 곳이 장점)
   - 비밀 값은 같은 콘솔의 Secret Manager로 (지금 `~/.config/tripfriends/server.env`를 옮김)
   - 도쿄: 1등급 지역이라 서울보다 싸고, 일본 여행 중 응답이 가깝다
2. **최소 인스턴스 0대로 시작**, 콜드 스타트를 감수. 사용량이 늘거나 콜드 스타트를 재 보고 너무 길면 그때 1대 (결정권자 11-16)
   - 참고 비용(가설, 도쿄·1 vCPU·1GiB·한 달 내내 1대): CPU 대기 약 $6.5 + 메모리 대기 약 $6.5 − 무료 약 $5 ≈ **월 약 $8**. 512MiB면 약 $5. 여행 기간에만 1대 켜는 설정도 가능
   - 돈 안 드는 완화: 앱 열기·"지금" 화면 진입 때 가벼운 요청으로 미리 깨우기 · 서버 시작 때 무거운 라이브러리 늦게 불러오기 · 실제 콜드 스타트 시간 측정
3. **Supabase는 무료 유지 + 크레딧 조금**
   - 무료 플랜이면 크레딧은 안 빠지고 그대로 남는다(만료 없음, 환불 없음). Pro로 올리는 순간부터 매달 약 $25가 크레딧에서 먼저 빠지고, 바닥나면 등록 카드로 넘어간다 → **바닥나기 전에 무료로 내릴 날짜를 기록**
   - 무료의 약점: 일주일 DB 사용이 거의 없으면 **일시 정지**(데이터·설정은 그대로, 대시보드 [Resume project]로 복구, 문서 기준 정지 후 1년 안). 하루 몇 번 요청이면 보통 충분
   - 파일럿 중엔 실제 사용이 있어 정지 걱정 없음. **Pro는 파일럿 핵심 1~2개월만** — 얻는 것은 자동 백업(실사용자 데이터 보호)
   - 파일럿 뒤엔 정지되게 두고 면접 시연 전날 [Resume]. 깨우기 스크립트는 문서가 허용·금지를 말하지 않아 쓰지 않는다
4. **LLM API·Serper도 선불 충전 대상** — 친구 대화(G3)·수집·평가 에이전트(ADR-018)는 무료 범위가 거의 없어, 실제 가장 큰 비용은 서버가 아니라 여기일 가능성이 높다

## 4. 예산 배분 (남은 약 35만 원, 가설 · 환율 약 1,450원/$ + 해외 결제 수수료)
| 항목 | 금액 | 메모 |
|---|---|---|
| Apple 개발자 계정 | 약 13만 원 | 1년. 결제 화면 원화 금액 확인 |
| 도메인 | 약 2만 원 | 1년 |
| Google Cloud 선결제 | 약 5만 원 | 여유분 (서버는 무료 사용량 안, 지도·Places는 SKU별 월 무료 호출량) |
| **LLM API 크레딧** | **약 10만 원** | TASK-016 수집 첫 회에서 실제 비용을 재고 다시 맞춤 |
| Supabase 크레딧 | 약 5만 원 | Pro 1~2개월 (파일럿 핵심 기간) |
| Serper | 0원 | 무료량 먼저, 모자라면 Google·Supabase에서 덜어 옴 |
| **합계** | **약 35만 원** | |
- 몽땅 많이 넣지 않는 이유: ① 환불 없음 ② 잔액이 크면 키 유출·버그로 새는 걸 늦게 안다(작은 잔액은 경보 역할) ③ Google 선결제 만료 조건이 문서에 없음
- **어떤 금액이든 예산 알림 + API 하루 한도는 건다** (ADR-017)

## 5. 결제 전 확인 (결정권자)
1. 학교 환급 규정이 선결제·크레딧 충전을 인정하는지, 영수증 형태, "활동 기간 안 사용" 같은 조건
2. Google 선결제가 한국 카드로 되는지, 만료가 있는지 (결제 화면)
3. Apple 개발자 계정 한국 결제 금액

## 6. 결과
- (+) 활동 기간이 끝나도 서버·지도·DB가 멈추지 않는다
- (+) 0대 시작이라 파일럿 서버비 ≈ 0, 예산을 실제 큰 비용(LLM)에 쓴다
- (+) 지도와 서버가 한 결제 계정 · 한 콘솔
- (−) 첫 요청 콜드 스타트 몇 초 (측정 후 판단) · Docker·권한 설정이 Fly.io보다 복잡 · 선불 잔액 관리(바닥 날짜) 필요

## 포트폴리오 포인트
- "어디가 유명하냐"가 아니라 **돈의 조건(활동 기간 뒤 결제 불가 → 선불)**을 첫 기준으로 8개 호스팅을 걸러 냄
- 콜드 스타트를 돈으로 바로 막지 않고 **비용을 계산(월 약 $8)하고, 0대로 시작해 측정 후 결정** — 미리 깨우기 같은 돈 안 드는 완화 먼저
- 서버보다 LLM이 큰 비용이라는 걸 예산 단계에서 찾아 배분을 바꿈

| 예상 면접 질문 | 답 |
|---|---|
| "왜 Cloud Run이었나요? AWS는요?" | 활동 기간 뒤엔 결제를 못 해서 선불이 되는 곳이어야 했고, AWS는 후불 카드가 기본이었습니다. Cloud Run은 선결제가 되고 0대까지 줄어 파일럿 비용이 거의 없고, 지도 API와 같은 결제 계정이라 관리가 한 곳이었습니다 |
| "콜드 스타트는 어떻게 했나요?" | 1대를 켜 두면 월 약 $8이라 계산해 두고, 먼저 0대로 시작해 앱 열 때 미리 깨우는 방식으로 줄였습니다. 실제 시간을 재서 길면 여행 기간에만 1대를 켜도록 정했습니다 |
