# ADR-016 · 계정: 익명으로 시작하고, 원할 때 계정 연결

| 항목 | 내용 |
|---|---|
| 상태 | **승인** — 결정권자 2026-11-09 · v1.1: R1은 Google만, 나머지는 파일럿 전 묶음 |
| 관련 | SRS FR-32·33 · ADR-013(앱 → 서버 → Supabase) · DATA-001 A(profiles) · API-001 공통(인증) · TASK-012 |

## 1. 문제
지금 여행은 서버 메모리에 기기 ID(`X-Device-Id`)로 저장된다. 서버를 다시 켜면 사라지고, 다른 기기에서 볼 수 없다. 저장소(Supabase)를 붙이면서 **사용자를 무엇으로 구분하고, 로그인을 언제 받을지** 정해야 한다.

## 2. 선택지
| 안 | 장점 | 단점 |
|---|---|---|
| A. 처음부터 로그인 (앱을 열면 로그인 화면) | 개발이 단순, 계정 연결 사고 없음, 파일럿 분석 쉬움 | 가치를 느끼기 전에 멈춤. 지금 흐름에 관문이 새로 생겨 화면·Maestro를 다시 짬. FR-32와 다름 |
| B. 둘러보기는 그냥, 여행 만들 때 로그인 (여행 앱에서 흔한 방식) | A보다 부담이 적음 | 계획 대화(설렘)를 해 보기 전에 멈춤 |
| **C. 익명 계정으로 시작 → 원할 때 Google·이메일로 연결** | **지금 앱이 이미 이렇게 동작**(기기 ID) → 사용자에게 바뀌는 것 없음. 계획을 해 본 뒤 저장을 권함. FR-32 그대로 | 익명 → 계정 연결에서 여행이 사라지는 사고 위험 → 규칙과 테스트로 막는다 |

## 3. 결정
**C.** Supabase Auth의 **익명 로그인**으로 시작하고, **R1은 Google**(앱 안 브라우저 OAuth)로 연결한다. **파일럿 전 묶음**: Apple 로그인(유료 개발자 계정·App Store 규칙), 이메일 6자리 코드(도메인 + SMTP를 그때 함께 연결), 카카오 로그인 검토(한국 사용자에게 익숙), 계정 삭제, **익명 로그인 캡차**(익명 계정 남용·MAU 비용 방지, Supabase 권고) (결정권자 11-09)

### 3-1. 연결 규칙
| 경우 | 규칙 |
|---|---|
| 새 계정에 연결 | 익명 계정의 여행이 그대로 옮겨진다 (같은 사용자 ID 유지) |
| 이미 있는 계정으로 로그인했는데 그 계정에도 여행이 있음 | R1은 여행 하나 → "어느 여행을 쓸까?"를 **한 번** 묻고, 고르지 않은 쪽은 **보관**(지우지 않음) |
| 연결 없이 앱을 지움 | 여행이 사라진다 → 첫 계획을 마치면 "저장해 둘래? 앱을 지우면 사라져"를 **한 번** 알린다 |

### 3-2. 권하는 때
- 첫 계획(코스 고르기)을 마쳤을 때 한 번. 조르지 않는다
- 사용자가 직접 프로필 메뉴에서 [저장하기]를 누를 때

### 3-3. 보안·개인정보
- 앱은 Supabase를 **로그인에만** 쓴다. 데이터는 모두 서버 API를 거친다 (ADR-013). 서버는 `Authorization: Bearer <Supabase JWT>`를 확인해 사용자를 구분한다 (`X-Device-Id` 대체)
- 앱에 들어가는 키는 **공개 키**(publishable/anon)뿐. 비밀 키(secret/service role)·DB 주소는 `apps/server/.env`에만
- 저장하는 개인정보: 계정 ID, (연결했다면) 이메일. 전화번호·실명·결제 정보 없음. 위치는 여전히 저장하지 않음
- OTA 제휴 링크(FR-37·38)는 계정 종류와 상관없다. 추적값이 필요하면 계정 ID만, 이메일은 넣지 않는다

## 4. 결과
- (+) 체험 → 저장이 자연스럽고, 지금 흐름을 거의 그대로 쓴다
- (+) 서버를 다시 켜도, 기기를 바꿔도(연결 뒤) 여행이 남는다
- (−) 연결 규칙 3가지를 테스트로 먼저 고정해야 한다
- (−) 이메일 코드 발송: Supabase 기본 메일은 **프로젝트 팀원 주소에만, 시간당 2통**(공식 문서 확인, 11-09) → 이메일 코드는 **파일럿 전 묶음에서 도메인 + SMTP(Resend 등)와 함께** 붙인다 (결정권자 11-09)
- 출시 전 할 일: Apple 로그인, 계정 삭제(App Store 규칙), 공개 출시 때 "로그인 화면에서 떠나는 비율"과 함께 재검토

## 포트폴리오 포인트
- "로그인 관문" 대신 **익명 계정 → 계정 연결**로 가치를 먼저 보여 주고, 데이터가 사라지는 세 경우를 규칙과 테스트로 막음

| 예상 면접 질문 | 답 |
|---|---|
| "회원가입을 왜 나중에 받았나요?" | 이 앱의 가치는 같이 고르며 계획하는 순간에 있어서, 그 전에 로그인을 요구하면 가치를 느끼기 전에 떠난다. 익명 계정으로 바로 쓰게 하고, 첫 계획 뒤에 저장을 권했다 |
| "익명 데이터를 계정에 붙일 때 문제는?" | 새 계정·이미 있는 계정·앱 삭제 세 경우를 규칙으로 정하고, 각 경우를 테스트로 먼저 썼다. 이미 있는 계정이면 어느 여행을 쓸지 묻고 다른 쪽은 지우지 않고 보관한다 |
