# ADR-013 · 시스템 구조: 앱(React Native) + 서버(Python FastAPI + LangGraph)

| 항목 | 내용 |
|---|---|
| 상태 | **Accepted** (2026-11-01 결정권자 승인) |
| 대체 | ADR-010(Next.js + Hono, 삭제) · ADR-013 초안(Python 에이전트 서비스 + MCP, 같은 날 단순화) |
| 관련 | ADR-012(에이전트 원칙, 유지) · PRD-001 §0·§4-6·§9 · TEAM-001 · PORTFOLIO-001 D-16·D-17 |

## 1. 배경
- 결정권자는 **프론트엔드와 AI 에이전트 개발자 직무를 같은 비중**으로 지원한다. 에이전트 직무 공고는 Python, LangGraph류 오케스트레이션, 도구 사용, RAG, 평가·모니터링을 반복해서 요구한다.
- 11-01 오전 초안은 TS 서버(Next.js + Hono) + Python 에이전트 서비스 + 엔진 MCP 서버였다. 혼자 4개월 안에 만들고 설명하기에는 **부품이 너무 많았다** (결정권자: "너무 복잡하다").

## 2. 결정
```
앱 (React Native, Expo, TypeScript)  ──HTTP·스트리밍──→  서버 (Python: FastAPI + LangGraph)  ──→  Supabase
                                                              │
                                                     (R2 이후) 웹 관측 대시보드 (Next.js)
```
1. **덩어리는 둘**: 앱(`apps/mobile`, TS)과 서버(`apps/server`, Python).
2. 서버 안에 전부 둔다: API(FastAPI), 에이전트 그래프(LangGraph), 엔진(규칙, 코스 계산 DP, 감지), 장소 수집, Jev·LLM 호출.
3. 엔진은 **LangGraph가 바로 부르는 Python 함수(도구)**다. MCP는 쓰지 않는다. 나중에 "엔진을 MCP 서버로도 공개"를 작은 추가 기능으로 둘 수 있다.
4. 타입 공유: 서버가 만드는 **OpenAPI 명세에서 앱용 TS 타입을 자동 생성**한다 (`packages/api-types`). 카드 스키마의 원본은 서버의 pydantic 모델이다.
5. **R2 이후** `apps/web`(Next.js)에 **에이전트 관측 대시보드**를 만든다: 대화 한 번이 거친 노드, 판단 정확도, 응답 시간, 비용. 웹 프론트엔드와 에이전트 평가를 한 화면에서 보여 준다.

## 3. 서버 안의 구성
| 모듈 | 내용 |
|---|---|
| `api` | FastAPI 엔드포인트, 인증(Supabase JWT 확인), 대화 스트리밍 |
| `graphs` | LangGraph: 대화 친구, 여행 중 재조합, 장소정보 수집 |
| `engine` | 규칙, 코스 계산(비트마스크 DP, 탐욕법 비교), 감지기. **LLM 없이 동작, TDD 대상** |
| `catalog` | 카드 12종 스키마 (pydantic) |
| `deciders` | `Decider` 인터페이스, `RuleDecider`, `JevDecider` (Jev 전용 타입은 밖으로 내보내지 않음) |
| `places` | 장소 DB 접근, 수집, 인용 대조 검증, 해설용 RAG |
| `evals` | 평가 세트와 측정 스크립트 |

| 그래프 | 노드 |
|---|---|
| 대화 친구 | 안전 규칙 → Jev 판단(대화/요청/되묻기) → 대화(LLM) · 요청(엔진 도구 → 카드) · 되묻기 |
| 여행 중 재조합 | 감지 사건 → 심각도(규칙, 11-03 정정: ADR-011에서 측정 안 된 자리는 규칙) → 재계산(DP) → 사용자 확인(interrupt) → 반영. 상세 GRAPH-001 |
| 장소정보 | 검색 → 읽기 → 추출(LLM) → 인용 대조 → 저장 (도구 5회 상한) |

## 4. 규칙
| 규칙 | 내용 |
|---|---|
| 진실의 원천 | 일정·장소·사용자 데이터는 **Supabase**. LangGraph 상태는 대화 맥락만. 일정 변경은 반드시 엔진 함수로 |
| 사실 값 | LLM 노드는 사실 값을 만들지 않는다. 엔진·DB 결과만 인용하고, 앱은 값을 칩으로 따로 표시 |
| 안전 | 안전 키워드는 그래프 첫 노드에서 규칙으로 처리. 모델을 거치지 않음 |
| 비밀값 | 키는 `apps/server/.env`에만. 앱(`apps/mobile`)에는 절대 두지 않는다 |
| 테스트 | 서버: pytest + Hypothesis + mutmut (엔진·라우팅 규칙·상한은 TDD). 앱: **Jest(`jest-expo`) + React Native Testing Library** (11-03 확정, Vitest는 RN 지원이 약해 제외), 속성 테스트 fast-check, 돌연변이 Stryker는 핵심 화면 로직만. E2E는 R1 후반 결정(Maestro 후보). LLM 노드는 평가 세트로 측정 |
| 지연 | 서버는 상시 실행 컨테이너. 대화는 스트리밍, 카드는 결과가 오는 대로 갱신. 응답 시간 측정 |
| 계약 | OpenAPI → `packages/api-types` 자동 생성. CI에서 생성 결과가 커밋본과 같은지 확인 |
| 배포 | 서버는 Docker 컨테이너 하나 (직접 운영 서버 또는 컨테이너 호스팅). 장소 수집은 같은 서버의 예약 실행 |

## 5. 검토한 대안
| 안 | 판단 |
|---|---|
| TS 서버(Next.js + Hono) 유지, 에이전트도 TS(LangGraph.js) | 언어 하나지만 에이전트 직무의 Python 요구를 못 채움 → 기각 |
| TS 서버 + Python 에이전트 서비스 + MCP (11-01 초안) | 직무 요구는 채우지만 덩어리 4개, 계약 2종, 서비스 간 지연 → **복잡도 때문에 기각** |
| **앱(TS) + 서버(Python) 두 덩어리** | 직무 요구를 채우고 단순함 → **채택** |

## 6. 잃는 것
- 서버리스 vs 컨테이너 비교(M-12)는 뺀다
- Next.js 서버 기능과 Hono 경험은 빠진다 → R2 이후 웹 관측 대시보드에서 Next.js를 다시 쓴다
- 10-16 "백엔드 TypeScript 전환" 결정을 되돌린다. 그때 이유(앱과 스키마 공유)는 OpenAPI 타입 자동 생성으로 대신한다

## 포트폴리오 포인트
- **보여주는 것**: 앱(TS)과 서버(Python LangGraph)로 나누고, 그래프로 흐름을 명시하고, 사실은 엔진·DB에서만 가져오며, 평가 세트로 측정한 구조. 그리고 **복잡한 초안을 스스로 줄인 판단**
- **흔한 방식과 차이**: "LLM에 도구를 다 주고 알아서 하게"가 아니라 안전 규칙 → 빠른 판단(Jev) → 필요한 노드만 LLM

### 예상 면접 질문과 답
| 질문 | 답의 뼈대 |
|---|---|
| 왜 앱은 TS, 서버는 Python인가요? | 앱은 RN이라 TS, 서버는 에이전트·RAG·평가 생태계가 강한 Python. 타입은 OpenAPI에서 자동 생성해 이어 붙였다 |
| 처음 설계와 무엇이 달라졌나요? | 처음엔 TS 서버 + Python 에이전트 + MCP로 나눴지만 혼자 운영하기엔 부품이 많았다. 덩어리를 둘로 줄이고 남는 시간을 에이전트 품질 측정에 썼다 |
| 왜 LangGraph인가요? | 자율 에이전트가 아니라 정해진 흐름이 필요했다. 노드·분기·체크포인트·사람 확인을 그래프로 명시하고, 실행을 추적해 평가할 수 있다 |
| 에이전트 품질은 어떻게 확인했나요? | 평가 세트로 판단 정확도, 사실 오류, 응답 시간, 비용을 쟀다 (값으로 채움) |
