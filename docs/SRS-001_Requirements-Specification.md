# SRS-001 · 요구사항 명세서 (v4, R1~R2)

| 항목 | 내용 |
|---|---|
| 상태 | **초안** — PM 작성 2026-11-02, 결정권자 검토 대기. 설문·인터뷰 후 개정 (변경 기록 §9) |
| 입력 | SCN-001(승인 11-02) · 근거 보고서 · PLAN-001 · PRD-001 · ADR-012·013 |
| 출력 | 화면 설계, 데이터 모델, 시스템 설계(API·그래프), 작업 지시서의 완료 기준 = 테스트 |
| 표기 | 우선순위 **M**(Must, R1 필수) · **S**(Should) · **C**(Could) · **L**(Later). **가설**은 설문·인터뷰로 확인 |

## 1. 범위
- **포함 (R1, 12월)**: 여행 만들기, 참여형 계획·자동 모드, 코스 계산, 여행 중 한 화면, 늦어짐 재조합, 방문 전 영업 확인, SOS, 계정·저장
- **포함 (R2, 1월)**: 대화 친구(채팅), Jev 판단, 날씨 감지, 현장 장소 검색, 영감 링크, 평가·추적
- **제외**: 여러 도시·여러 날 연결 일정, 예약·결제 대행, 다국어 UI(구조만 준비), 사람 매칭, 범용 자율 에이전트
- **첫 시장**: 일본 대도시 1곳(설문 후 결정), 한국어

## 2. 용어
| 용어 | 뜻 |
|---|---|
| 여행 | 도시·날짜·숙소를 가진 한 번의 여행 |
| 일정 항목 | 하루 코스 안의 장소 방문 하나 (시작·끝 시간, 이동) |
| 고정 일정 | 예약·공연처럼 시간을 바꿀 수 없는 항목. 재조합 때 지킨다 |
| 후보 | 취향·조건에 맞아 사용자에게 보여 주는 장소 |
| 재조합 | 지금 위치·시간에서 남은 일정을 다시 계산하는 것 |
| 사실 값 | 영업시간, 휴무, 가격, 위치, 이동 시간처럼 틀리면 안 되는 값 |
| 확인 상태 | 사실 값의 상태: 확인됨(출처·날짜) / 미확인 / 모름 |

## 3. 기능 요구사항
### 3-1. 여행과 계획 (S1·S2 · 문제 ①)
| ID | 요구사항 | 우선 | 시나리오 |
|---|---|---|---|
| FR-01 | 사용자는 도시, 날짜, 숙소(선택), 꼭 갈 곳(0개 이상)을 입력해 여행을 만든다 | M | S1·S2 |
| FR-02 | **대화형 계획** (11-02): 친구가 질문하고 → 찾아 오고 → 사용자가 반응하고 → 다시 찾는 반복으로 계획한다. 질문은 **고를 수 있는 보기 버튼**으로 하고, [직접 말할래]로 글 입력도 받는다. **R1은 정해진 대본(질문 순서 + 버튼) + 엔진**, R2는 LangGraph + LLM으로 자유 문장 이해 | M | S1 |
| FR-02a | 찾아 온 후보는 한 번에 **5~6개**를 옆으로 넘기는 카드 묶음으로 보여 준다. 카드에는 사진, 이름, 한 줄 설명, 영업 정보와 확인 상태, [좋아] 버튼. 마음에 안 들면 그냥 넘긴다 | M | S1 |
| FR-02b | **이유를 묻지 않는다.** 넘긴 곳과 [좋아]한 곳의 차이(혼잡, 거리, 가격, 분위기 등 속성)로 취향을 추정해 다음 후보 점수에 반영한다 (암묵적 피드백) | M | S1 |
| FR-02c | 카드 묶음 아래 **방향 버튼**: "다음엔 어떤 쪽으로 찾아볼까?" + 지금 후보에 맞게 바뀌는 버튼 2~3개(예: [좀 더 한적한 데] [숙소랑 가까운 데] [완전 다른 느낌]) + **[직접 말할래]**. 누르면 그 방향으로 다시 찾는다. 직접 입력은 R1에서 **키워드 규칙**(한적·조용 → 혼잡 낮음, 가까운 → 거리, 싼 → 가격 등)으로 해석하고, 모르면 "이 중에 있어?" 버튼으로 되묻는다. R2는 LLM이 해석. [좋아]한 곳은 "담은 곳"으로 화면 위에 쌓인다 | M | S1 |
| FR-03 | 방향 버튼과 따로 있는 큰 버튼 **[담은 곳 n개로 코스 짜 줘]**를 누르면, 담은 곳으로 **코스 2~3안**(예: 여유 / 알차게)을 만든다. 사용자는 하나를 고른다. 다른 날은 쌓인 취향으로 이어서 짠다 | M | S1 |
| FR-04 | 시스템은 고른 장소를 고정 장소로 넣고 하루 코스를 계산한다 (거르기 → 점수 → 고정 → DP). **R1 점수는 취향 가중치 규칙 점수**, Jev 점수는 POC-001 결과로 R2에서 결정 | M | S1·S2 |
| FR-05 | 자동 모드: 첫 질문의 **[알아서 짜 줘]** 버튼으로 대화를 건너뛰고 꼭 갈 곳만으로 코스 2~3안을 바로 만든다 | M | S2 |
| FR-06 | 사용자는 코스의 장소 하나를 "바꾸기"로 같은 종류 대안 3곳(동선 변화 표시) 중 하나로 바꾼다 | M | S2 |
| FR-07 | 코스가 불가능하면(시간 부족, 영업시간 겹침 없음) 이유와 뺄 후보를 제안한다 | M | S1 |
| FR-07a | **머무는 시간은 그날 일정에 맞게 자동으로 정하고, 사용자가 바꿀 수 있다.** 장소마다 머무는 시간 범위(최소·보통·최대)가 있고(장소 값 > 종류 기본값), 코스 계산이 그날 쓸 수 있는 시간·영업시간·고정 일정에 맞게 범위 안에서 나눠 정한다. 속도(느긋하게/꽉 채워서)는 범위 안 위치와 장소 사이 쉬는 시간으로 반영. 코스안에서 시간을 누르면 ±15분 단위로 바꾸고, 뒤 일정을 다시 계산해 빠지는 곳이 생기면 바꾸기 전에 알려 준다. 고정 일정 시간은 바꾸지 않는다 | M | S1 |
| FR-08 | 첫 질문에서 대화형과 [알아서 짜 줘] 중 무엇을 앞에 둘지 (**설문 9번 결과로 결정**) | S | S1·S2 |
| FR-09 | 친구와 후보를 공유해 같이 고르기 | L | — |

### 3-2. 여행 중 (S3·S4 · 문제 ②③)
| ID | 요구사항 | 우선 | 시나리오 |
|---|---|---|---|
| FR-10 | 여행 중 한 화면: 고정 영역(프로필, SOS, 입력창) + 상황에 맞는 카드 (지금 할 일, 다음 이동, 남은 일정) | M | S3 |
| FR-10a | **상황에 맞게 화면을 조합한다 (능동형 UI, PRD §4).** 카드 카탈로그에서 지금 상황에 맞는 카드를 골라 "상황 → 판단 → 행동" 순서로 한 화면을 만든다. **분명한 상황은 규칙**(늦어짐, 고정 일정 임박, 이동 중, 도착, 오프라인), **애매한 상황은 Jev**(예: 다음 일정까지 40분 여유, 비 예보 + 실내·실외 일정 섞임). R1은 규칙만, R2에서 Jev를 얹어 비교 | M (R1 규칙) / M (R2 Jev) | S3·S4 |
| FR-10b | 화면 조합 가드레일 (PRD §4-3): SOS·입력창·프로필 위치 고정, 장소에는 확인 상태 필수, 조합 영역 카드 5개 이하, 읽는 순서 고정, **Jev 응답 0.5초 초과나 확률 기준 미달이면 규칙 기본 구성** | M | — |
| FR-10c | 같은 조합 원리를 계획 대화의 **방향 버튼**(지금 후보에 맞는 버튼 고르기)과 대화 요청 결과 카드에도 쓴다 | S (R2) | S1·S5 |
| FR-11 | 시스템은 현재 시간·위치와 일정을 비교해 **늦어짐을 감지**한다 (규칙: 다음 항목 시작까지 이동 시간이 모자람) | M | S3 |
| FR-12 | 늦어짐이면 **고정 일정을 지키는 대안 2~3개**를 계산해 카드로 보여 주고, 각 대안에 이유 한 줄을 붙인다 | M | S3 |
| FR-13 | 사용자가 대안을 고르면 일정에 반영한다. 고르지 않으면 바꾸지 않는다 (자동 변경 금지) | M | S3 |
| FR-14 | 미확인 장소는 출발 전에 **방문 전 영업 확인 카드**(출처·확인 날짜·"모름", 원래 지도 링크)를 띄운다 | M | S4 |
| FR-15 | "영업 중이었나요?" 답을 받고, 닫혔으면 근처 같은 종류 대안 3곳을 제안한다. 답은 장소 DB에 사용자 확인으로 저장 | M | S4 |
| FR-16 | 마지막 일정 뒤 **숙소 가는 방법 한 줄**(마지막 교통 시각 또는 대안)을 항상 보여 준다 | M | S3 |
| FR-17 | 교통 시간표가 있는 도시는 막차를 감지해 알린다. 없으면 FR-16으로 대신 (**도시 데이터 조사 후 결정**) | S | S3 |
| FR-18 | 날씨 예보가 야외 일정과 겹치면 알리고 대안을 제안 | S (R2) | — |
| FR-19 | 같은 사건은 한 번만 알리고, 심각도 높은 것만 푸시 알림 | M | S3 |
