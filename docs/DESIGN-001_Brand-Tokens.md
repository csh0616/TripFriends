# DESIGN-001 · 브랜드 색과 디자인 토큰 출발점

| 항목 | 내용 |
|---|---|
| 상태 | **v1** — PM 2026-11-05. 기존 데모(tripfriends-front.vercel.app)에서 **색과 로고만** 가져옴. 나머지(글꼴·간격·부품)는 디자이너 세션이 새로 정한다 |
| 작업 방식 (11-05 결정) | 디자이너 세션은 **저장소 밖 별도 폴더** `~/Documents/TripFriends-design`(git 없음)에서만 작업. 저장소는 읽지도 쓰지도 않음. 시안·토큰은 그 폴더에만 두고 **git에 올리지 않는다**. 확정된 값은 PM이 이 문서 §4에 옮기고, 저장소의 토큰 파일은 TASK-004에서 `frontend`가 만든다 |
| 결정권자 지시 | 기존 디자인을 그대로 쓰지 않는다. 디자인 에셋(색·로고)만 가져오고 화면은 SCREEN-001 구조로 새로 설계 |
| 관련 | SCREEN-001 §2-1(의미 색), TEAM-001 §2(designer), TASK-004 입력 |
| 로고 | 디자이너 폴더 `ref/logo-white.png` (흰색, 투명 배경, 669×373). 밝은 배경용 버전은 디자이너가 만든다. 저장소에는 TASK-004에서 확정본만 넣는다 |

## 2. 의미 색 (SCREEN-001 §2-1 유지, 톤만 브랜드에 맞춤)
| 뜻 | 글자 / 배경 | 쓰는 곳 |
|---|---|---|

| 미확인 | `#92400E` / `#FEF3C7` | 사실 칩 |

- 모든 글자는 배경과 대비 4.5:1 이상 (11px 라벨 포함)

## 3. 디자이너가 정할 것
글꼴(한글 포함), 글자 크기 체계, 간격, 모서리, 그림자, 기본 부품 모양, 다크 모드 여부(R1은 라이트만 권장). 확정되면 이 문서에 §4로 추가한다

## 포트폴리오 포인트
- 디자인 작업을 코드 저장소와 **물리적으로 분리**(별도 폴더, git 없음, 권한 제한) → 디자인 탐색이 코드에 섞이지 않음
- 확정된 토큰만 저장소로 → `frontend`는 토큰만 쓰고 `reviewer`가 토큰 밖 색을 잡는다
- 예상 면접 질문: "디자인 시스템을 왜 만들었나요?" → "에이전트가 화면을 여러 개 만들면 스타일이 흩어진다. 토큰 파일 하나로 묶고 리뷰에서 검증했다"
