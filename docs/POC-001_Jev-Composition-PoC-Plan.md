## 1. Jev 후보 역할
| 역할 | 어디서 | 대안 |
|---|---|---|
| A. 대화/요청/되묻기 판단 + **어떤 카드로 답할지** (우선 높음) | 채팅 입력 라우터 (R2, FR-21·24·10c). "대화하면 화면이 조합된다" | 작은 LLM, 키워드 규칙 |
| B. 방향 해석 (우선 높음) | 계획 대화의 [직접 말할래] (FR-02c) | R1 키워드 규칙, LLM |
| C. 후보 점수 (선택) | 코스 계산 전 후보 순위 | R1 규칙 점수(취향 가중치) |
| **D. 화면 카드 조합 (능동형 UI)** (우선 중간) | 여행 중 한 화면의 애매한 상황에서 어떤 카드를 어떤 순서로 (FR-10a) | R1 규칙 기본 구성, LLM 생성 |

R1은 Jev 없이 규칙만으로 동작한다. 검증 결과는 R2에서 Jev를 어디에 넣을지 정하는 근거다.

### 1-1. Jev 확장 원칙 (11-02 결정권자)
기능을 바꾸거나 추가하다가 **"정해진 보기 중에서 고르기 / 점수 매기기 / 예·아니오"** 형태의 판단이 생기면 Jev 후보로 아래 등록부에 올린다. 같은 정답 데이터로 규칙(또는 LLM)과 비교해 더 나을 때만 넣는다. 안전·사실 값·코스 계산에는 쓰지 않는다.

| 등록일 | 후보 판단 | 형태 | 비교 대상 | 상태 |
|---|---|---|---|---|
| 11-02 | A·B·C·D (위 표) | choice / score | 규칙, LLM | A·B 측정 완료 (§6) → ADR-011 제안. C·D 미측정 |

### 해석
- **A의 틀린 답은 거의 "되묻기"에서 나왔다.** 정답이 되묻기인 7문장 중 1개만 맞춤. "되묻기"를 하나의 보기로 주는 설계가 문제일 가능성이 크다 → **대화/요청 2분류 + 확률이 낮으면 되묻기**로 바꿔 재측정 (FR-24 원래 의도와 같음). 정답 초안 자체가 애매한 문장도 있음 (예: "배고파"는 여행 앱에선 요청일 수도)
- **B는 규칙이 이겼다. 단, 공정한 비교가 아니다.** 키워드 목록을 테스트 문장을 보고 만든 같은 사람(PM)이 썼다 → 규칙이 시험 문제에 맞춰진 상태. **새 문장 20개(결정권자 작성, 규칙 고정 후)**로 다시 비교해야 함. Jev는 "싼 데", "쉬어 갈 데", "힙한 데"를 unknown으로 답함 → 보기 설명을 다듬을 여지
- **둘 다 여러 방향(예: "가까운데 조용한 데")은 하나만 답함** → 방향을 하나 고르는 대신 방향별 예/아니오(noul)로 묻는 설계도 후보

| 한계 | 6명은 작은 표본, 가상 데이터, 정답도 AI. 실제 효과는 R2에서 [좋아] 비율로 다시 잼 |

### 7-1. 규칙 점수식 (정답을 보기 전에 고정)
- 태그 가중치: 좋아한 곳의 태그마다 +1, 넘긴 곳의 태그마다 −1 (겹치면 합산)
- 종류: 좋아한 곳의 종류와 같으면 +1, 넘긴 곳의 종류와만 같으면 −0.5
- 붐빔·가격: 좋아한 곳 평균과의 차이 × −0.5 (좋아한 곳이 없으면 0)
- 점수 = 후보 태그의 가중치 합 + 종류 점수 + 붐빔 항 + 가격 항. 동점은 ID 순
- 이 식은 결과를 본 뒤 바꾸지 않는다 (§5-1 교훈)

### 7-2. 결과 (결정권자 맥 실측, 18회 호출)
| 지표 | 규칙 | Jev score | 섞기 (규칙 6곳 → Jev 순서) |
|---|---|---|---|
| 상위 3 겹침 | 55.6% | **61.1%** | 61.1% |
| 1위 적중 | **67%** | 50% | 50% |
| 정답 확신 상·중만 (5명) | 53.3% | 66.7% | — |

- Jev 일관성 (3회 반복 상위 3 동일): 4/6. 확신도 평균 **0.57**
- 지연 (12문항 한 번 호출): p50 574ms, p95 690ms. 비용 호출당 약 $0.0001 (12문항)
- **판정: 기준 미달 (+5.5%p < +15%p) → 규칙 유지.** 차이 5.5%p는 18칸 중 1칸으로, 표본 잡음 수준
- 정답 확신이 상·중인 여행자만 보면 +13.4%p로 기준에 가깝다. 실제 장소 설명 글이 생기면 다시 잴 가치는 있음 (R2, [좋아] 비율로)
- 정답 이상: S5 정답에 넘긴 곳(줄 서는 라멘)과 비슷한 "미슐랭 라멘"이 포함. 결과 전에 정한 정답이라 그대로 둠

### 7-3. 첫 시도 실수 (기록)
- 1차: `criteria` 누락 → 400 (`expected array`)
- 2차: criteria에 **평가 항목 3개**를 넣음 → Jev 0% (무작위 25%보다 낮음), 확신 0.05
- 원인: Jev `score`는 criteria를 **순서 있는 척도**로 읽는다. 응답 `legend`가 0~n을 각 문장에 대응시키고, `score`는 척도 위치의 기댓값(Σ i×p_i)
- 3차: 척도 `전혀 안 맞는다 → 조금 → 꽤 → 아주 잘`로 바꾸고, 평가 항목은 instructions로 옮김 → 위 결과. 정답·규칙식은 바꾸지 않음
- 교훈: **새 질문 형식은 응답 모양부터 확인한다.** TASK-001의 Jev 클라이언트에 score 척도 형식을 명시

## 8. 역할 D (메인 카드 고르기) 측정 (2026-11-02)
**질문**: 애매한 여행 중 상황과 요청 문장에서, 화면 맨 위 메인 카드 1장을 Jev가 규칙보다 잘 고르나? (SCREEN-001 §4·§7)

| 항목 | 내용 |
|---|---|
| 데이터 | 20개. 분명 K1~K5(규칙 확인용, Jev 안 부름) · 애매 A1~A8(PM 작성) · 요청 R1~R7(**Gemini가 문장 작성**) |
| 보기 | T-01~T-13 (SCREEN-001 §3-2). 정답자와 Jev가 같은 보기를 씀 |
| 정답 | Gemini + 두 번째 AI가 각각 고름. 갈리면 '경계'. PM은 정답을 달지 않음 |
| 채택 기준 (가설) | Jev 정확도 80% 이상 **그리고** 규칙보다 +15%p, p95 0.8초 이하 |

### 8-1. 규칙 (정답·요청 문장을 보기 전에 고정)
- 분명 상황: SCREEN-001 §4-1 우선순위 표
- 애매 상황: 규칙 기본값 **T-01** (SCREEN-001 §4-2)
- 요청 문장: 키워드를 아래 순서로 확인, 처음 맞는 것. 없으면 T-13
  1. T-10: 배고, 먹, 밥, 식당, 점심, 저녁, 맛집
  2. T-09: 피곤, 쉬, 다리, 힘들, 앉
  3. T-08: 숙소, 호텔, 집에, 들어가, 막차
  4. T-12: 비, 우산, 날씨
  5. T-04: 바꿔, 늦, 취소, 빼
  6. T-02: 다음, 어디로, 출발
  7. T-03: 남은, 오늘 일정
  8. T-11: 심심, 시간 남, 뭐하지

### 8-2. 결과 (결정권자 맥 실측, 60회 호출)
정답: Gemini와 두 번째 AI가 20개 중 17개 일치. 경계 3개(A1·A5·A7)는 둘 중 하나면 정답

| 묶음 | 규칙 | Jev (확신 0.6 미만 되묻기) | Jev (기준 없이) |
|---|---|---|---|
| **애매+요청 15개 (사전 기준)** | 20.0% | 60.0% | 66.7% |
| 요청 문장 7개 (사용자의 말 있음) | 42.9% | **100%** | 100% |
| 애매 상황 8개 (말 없음) | 0% | 25.0% | 37.5% |
| 정답자 일치 12개만 | 25.0% | 75.0% | — |
| 분명 5개 (참고) | 100% | — | 100% |

- 되묻기 비율 33.3% (모두 애매 상황에서 발생). 확신 평균 0.79, 일관성 18/20, p50 493ms, p95 632ms, 호출당 약 $0.00003
- **사전 기준(15개 80%)은 미달.** 다만 두 묶음의 차이가 크다: 말이 있으면 100%, 말이 없으면 37.5%. 묶음별 집계는 측정 전에 요약에 넣어 두었으나, 묶음별 채택 기준은 사후 판단이다
- Jev가 틀린 5개: A1·A5 → T-07(고정 일정 임박), A3 → T-02(다음 이동), A2·A6 → T-11(여유 시간). **"다음 일정"이라는 단서에 끌리고, 식사 시간·걸은 거리 같은 숨은 필요는 놓친다**
- 키워드 규칙의 실패 예: R2 "시간 다 **까먹**음" → "먹"을 잡아 먹을 곳(T-10)

### 8-3. 판단
| 묶음 | 결정 | 이유 |
|---|---|---|
| 요청 문장 → 메인 카드 (R2) | **Jev 채택** | 100% vs 규칙 42.9%. 실제 말투에서 키워드 규칙은 더 약해짐 |
| 애매 상황 → 메인 카드 | **Jev 기각**, 상황 규칙 후보로 | 37.5%. 놓친 것(식사 시간대, 많이 걸음)은 명시적 조건이라 규칙으로 쓸 수 있음. 단, 이 20개를 본 뒤 만든 규칙이므로 **새 상황으로 검증 필요** |

### 8-4. 상황 규칙 검증 계획 (새 상황, Jev 없음)
- 상황 규칙은 SCREEN-001 §4-2a를 **위에서부터 처음 맞는 것**으로 적용. 이 문서 시점(새 상황을 보기 전)에 고정
- "다음 일정까지"는 이동 시간을 포함한 분, "여유"는 그 값에서 이동 시간을 뺀 분
- 새 상황 12개는 Gemini가 구조화된 값(시간, 다음 일정까지 분, 이동 분, 걸은 km, 이번 끼니 먹음 여부, 2시간 안 강수 확률, 실외 일정 남음, 남은 일정 수)과 함께 쓰고 정답을 단다. 규칙 내용은 알려 주지 않는다
- 비교 기준선: 기존 기본값 T-01. 채택 기준 (가설): 상황 규칙 75% 이상

### 8-5. 상황 규칙 검증 결과 (새 상황 12개, 정답 Gemini 1명)
| 방식 | 정확도 |
|---|---|
| 기본값 T-01만 | 2/12 (16.7%) |
| **상황 규칙 (§4-2a 고정)** | **4/12 (33.3%) → 기준 75% 미달** |

- 실패의 대부분은 마지막 줄 **"여유 30분 이상 → T-11 여유 시간 제안"**: 7번 발동해 0번 맞음. 정답자는 여유 시간에 다음 이동(T-02), 남은 일정(T-03), 기본(T-01), 쉴 곳(T-09)을 골랐다. 여행 중 여유는 평소 상태이지 특별한 신호가 아니다
- **강한 신호 규칙**(식사 시간 + 안 먹음, 비 + 실외, 10km 이상, 일정 끝)은 5번 발동해 4번 맞음 (정밀도 80%). 틀린 1번은 15:20에 일정이 끝난 경우(T-08 vs 정답 T-11) → 시간대 조건 필요
- 정답 자체도 흔들림: 12개 중 '중·하' 확신 6개. N7은 다음 일정이 "저녁 식사"인데 정답이 먹을 곳. §8-2의 애매 상황에서도 두 AI가 8개 중 3개에서 갈렸다
- **해석**: "아무 일도 없을 때 무엇을 먼저 보여 줄까"는 정답이 하나인 문제가 아니다. 규칙도 Jev도 높은 정확도를 낼 수 없다

### 8-6. 판단 (사후, 사용 테스트로 확인)
| 항목 | 결정 |
|---|---|
| 애매 상황의 메인 카드 | **바꾸지 않는다** (T-01 기본 + 짝 카드). 화면 안정 우선 |
| 강한 신호 4개 | 메인 카드로 올린다 (정밀도 80%, 표본 5). "일정 끝 → 숙소" 는 18시 이후로 제한 |
| 약한 신호 (여유 시간, 7~10km 걸음, 식사 시간 근처) | 메인을 바꾸지 않고 **제안 칩 1개**로: "배고프면 근처 먹을 곳 볼래?" 누르면 해당 카드 |
| 측정 | R2 사용 테스트에서 제안 칩 누름 비율, 강한 신호 카드 무시 비율 |


## 9. 서버 연동 첫 확인 (TASK-001 AC-19, 11-03)
- 서버의 `JevDecider`로 첫 호출: **3.24초 → 0.8초 제한에 걸려 규칙 대체로 넘어감**. 두 번째 호출 0.95초 통과 (`pick=request`)
- 측정 스크립트의 p95 630~730ms는 연결이 이미 열린 상태 값이었다. **첫 연결(보안 연결 준비) 비용은 측정에 없었다**

- 교훈: 측정 환경(스크립트)과 실제 환경(서버)의 차이를 따로 확인해야 한다
