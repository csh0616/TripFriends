## T. 테스트용 DB
- 테스트는 **실제 Supabase 클라우드에 붙지 않는다**. 로컬 Postgres(Docker 또는 Supabase CLI `supabase start`)에 붙는다
- 메인 세션이 먼저 `docker`·`supabase` 명령이 있는지 확인. 없으면 설치 방법 2가지(Docker Desktop / OrbStack)와 크기를 결정권자에게 보고하고 기다린다
- DB 테스트는 표시(`db`)를 달아, DB가 없으면 건너뛰고 이유를 한 줄 출력

## 10. 질문 답 (11-10, 1단계 test-writer Q1~Q12) · 테스트 승인
**승인**: 미리 바꾼 기존 테스트(X-Device-Id → Bearer, "헤더 없음 400" → "토큰 없음 401"), 테스트 도구(`db` 표시, Supabase 가짜, 기기 초기화가 세션도 비움), 빈 껍데기 이름(`verify_token`, `PostgresPlanningRepo`, `PostgresTripRepo`), `DATABASE_URL` 있으면 Postgres·없으면 메모리, `apps/mobile/CLAUDE.md`의 `EXPO_PUBLIC_` 허용 목록에 `SUPABASE_URL`·`SUPABASE_KEY`(+ 점검용 `CHECK_` 둘) 추가

| Q | 답 |
|---|---|
| 1 장소·좌표 | DB에는 `place_id`(와 우리 장소 id)만. 읽을 때 **도시 팩 + 좌표 캐시(30일) + 영업시간 메모리(1시간)**에서 되살린다(TASK-010 §11 그대로). 숙소 좌표도 좌표 캐시, 없으면 다시 부름 |
| 2 JWT 방식 | **비대칭 키(JWKS)를 기본**으로: `{SUPABASE_URL}/auth/v1/.well-known/jwks.json`에서 공개 키를 받아 확인(캐시). **결정권자 확인(11-10): 클라우드 프로젝트는 ECC(P-256) 비대칭 키** → `SUPABASE_JWT_SECRET` 필요 없음. 로컬 Supabase도 같은 방식으로 맞춘다(안 되면 보고). `aud="authenticated"` 확인, 만료는 **여유 10초** |
| 3 오류 code | 401 = **`UNAUTHORIZED`**, DB 못 붙음 503 = **`STORAGE_UNAVAILABLE`** (숙소 검색의 `PROVIDER_UNAVAILABLE`과 나눔). PM이 API-001에 추가 |
| 4 인증 범위 | **사용자 데이터를 읽거나 바꾸는 모든 API**(여행·날·고정 일정·계획·여행 중 check/accept/dismiss·영업 확인)와 **장소 검색·숙소 검색**(Google 호출 비용 남용 방지)은 Bearer 필요. `/health`·`/catalog`는 필요 없음. `/debug/seed-demo`는 토큰 없이도 되고, 있으면 그 사용자 여행으로 붙임 |
| 5 데모 시드 | 맞음. 로그인 없는 데모 여행은 주인 비움(`owner_id` null) — **`is_demo=true`일 때만** 허용 (테스트로 고정) |
| 6 B4 끝 | **바꿈: 기기에 세션이 있으면 새 익명 계정을 자동으로 만들지 않는다** (만들면 연결 전 여행을 잃음). 401 → 토큰 새로 받기 → 다시 한 번 → 그래도 401(또는 새로 받기 실패)이면 "로그인 정보를 확인하지 못했어" + [다시]. 새 익명 로그인은 **기기에 세션이 없을 때만** |
| 7 익명 로그인 재실패 | 여행 만들기에서 다시 해도 실패하면 "지금 연결이 안 돼. 잠시 뒤에 다시 해 줘" + [다시], 입력값 그대로 |
| 8 메모리 되돌림 | **메모리도 되돌린다** (같은 계약 테스트를 두 구현에) |
| 9 마이그레이션 위치 | 저장소 맨 위 **`supabase/migrations/`** (Supabase CLI 기본) |
| 10 `decision_logs` | **1단계에 넣는다** (이미 쓰고 있음) |
| 11 `is_demo` 응답 | 여행 응답에 **`is_demo`** 넣는다 |
| 12 만들기 503 | 같은 문장 "지금 저장소에 못 붙었어" + [다시], 입력값 그대로 |

## 11. 질문 답 (11-10, 데모·남의 것) — **§10 Q5를 바꿈**
권고(주인 없는 데모의 계획 길만 토큰 없이 열기) 대신 **토큰 없이 열린 길을 하나도 만들지 않는다**. 앱은 늘 익명 로그인이 되어 있으니 데모도 토큰을 실을 수 있고, 데모는 개발 빌드에서만 있다(운영 404)

| Q | 답 |
|---|---|
| 1 로그인 없는 데모 | **없앤다.** 데모도 토큰 필요. 주인 없는 여행(`owner_id` null)은 **아예 허용하지 않음** (§10 Q5 대체). 계획·여행 중 API는 예외 없이 Bearer |
| 2 앱 데모 버튼 | 토큰을 싣는다. 서버는 데모 여행을 **그 사용자 소유로 만들되 지금 여행을 바꾸거나 보관하지 않는다**(`is_demo=true`, `/trips/current`에 안 나옴). 점검(Maestro)이 "지금 여행으로 붙이기"가 필요하면 **명시 값 `as_current: true`**일 때만 (TASK-010 §15의 점검 전용 동작 그대로) |
| 3 남의 날·계획 세션 | **404 `NOT_FOUND`** (있는지 알리지 않음). 여행·날·계획 세션·고정 일정·사건 모두 |
| 작은 질문 | 만료 + 10초 정각은 거절 — 그대로 |

## 12. 1단계 구현 보고 답 (11-10)
| # | 답 |
|---|---|
| 1 계획·여행 중 안내 문장 | **모든 화면 같게**: 두 번째 401 → "로그인 정보를 확인하지 못했어" + [다시], 503 `STORAGE_UNAVAILABLE` → "지금 저장소에 못 붙었어" + [다시], 그 밖 500 → 기존 "잠깐 문제가 생겼어" |
| 2 API 문서 길 | 개발은 열어 둠. **`APP_ENV=production`이면 `/docs`·`/redoc`·`/openapi.json` 끔** (공개 서버에 API 지도를 내놓지 않음, ADR-017) |
| 3 데모를 `archived`로 | **바꿈**: `archived`는 "사용자가 보관한 여행" 뜻이라 섞지 않는다. 데모는 `active` + `is_demo=true`, **"지금 여행" = `active`이면서 `is_demo=false`** (`as_current: true`일 때만 예외) |
| 4 재시작 비교에서 영업시간 뺌 | 승인 (메모리 1시간이 정상 동작) |
| 5 `TripBook.own_days` | **제품 코드에서 뺀다** → 테스트 도우미(fixture)로. 제품 코드에 테스트 전용 길을 두지 않는다 |
| 6 공개 키(JWKS)를 못 받을 때 | **503 `AUTH_UNAVAILABLE`** (401 아님 — Supabase 장애를 "로그인 틀림"으로 보이면 안 됨). 앱은 "지금 연결이 안 돼. 잠시 뒤에 다시 해 줘" + [다시]. 모르는 키 ID면 60초에 한 번 다시 받기 — 승인, **이 기능에 테스트를 더한다**(살아남은 돌연변이 17개) |
| 7 API-001 seed-demo | PM이 고침 |

## 포트폴리오 포인트
- 저장소 인터페이스 하나에 메모리·Postgres 두 구현, **같은 계약 테스트**로 바꿔 끼움을 증명
- "실패한 요청은 아무것도 바꾸지 않는다"를 메모리에서 DB 트랜잭션까지 이어서 보장 (TASK-003 R12의 남은 한계 해결)
- 익명 → 계정 연결에서 데이터가 사라지는 경우를 규칙·테스트로 먼저 막음 (ADR-016)

| 예상 면접 질문 | 답 |
|---|---|
| "메모리 저장소에서 DB로 어떻게 옮겼나요?" | 처음부터 저장소 인터페이스를 두고 메모리 구현으로 시작했다. DB 구현을 더하고 같은 계약 테스트를 두 구현에 돌려 동작이 같음을 확인했다 |
| "저장 중에 실패하면?" | 요청 하나를 트랜잭션 하나로 묶었다. 테스트에서 일부러 중간에 예외를 내 DB가 요청 전과 같은지 확인했다 |
