## A. 실제 위치 (앱)
| # | 할 것 |
|---|---|
| A1 | **언제 묻나**: 실제 여행의 **오늘** 여행 중 화면을 처음 열 때, 안내 시트 한 번(§D1) → [위치 켜기]를 누르면 iOS 권한 창. **"앱을 사용하는 동안"만** 요청(백그라운드 요청 없음). 데모 여행·계획 화면·앱 처음 켤 때는 묻지 않음 |
| A2 | **거절·나중에**: 지금처럼 **시계만** 쓰는 모드(TASK-010 C4) 그대로. 화면에 작은 알약 "위치 꺼짐"(§D2) → 누르면 설명 + [설정 열기]. 다시 묻는 시트는 자동으로 띄우지 않음 |
| A3 | **언제 위치를 읽나**: 여행 중 화면이 **앞에 있을 때만**. 가설: 50m 넘게 움직였거나 1분이 지났을 때 → `POST /days/{day_id}/check` 본문으로. 화면을 떠나거나 앱이 백그라운드로 가면 읽기를 멈춘다 |
| A4 | **정확도**: 정확도가 100m보다 나쁘면(가설) 그 위치는 쓰지 않고 시계만 (오탐으로 "늦었어"를 띄우지 않기) |
| A5 | **위치가 쓰이는 곳**: 늦어짐 감지(FR-11), 다음 장소 도착 판단, SOS 시트의 "지금 위치"(주소 변환은 TASK-015에서, 이번엔 좌표가 있으면 "위치 확인됨"만) |

## C. 이 날 미리 걸어 보기 (연습 모드)
| # | 할 것 |
|---|---|
| C1 | **들어가는 곳**: 날짜 목록에서 **계획 완료(코스를 고른) 날** 줄 → [미리 걸어 보기] (§D3). 오늘·지난 날·계획 전 날엔 없음. 데모 여행엔 이미 데모 시계가 있으니 없음 |
| C2 | **화면**: 여행 중 화면(SC-04)과 같은 화면 + **"연습 중" 띠**(§D4) + 시계 막대(데모 시계 B7 재사용: 하루 시작~끝, [+10분], [▶ 재생]). 위치는 `fake-position.ts`(코스대로)로. [연습 끝내기]로 날짜 목록 |
| C3 | **저장 0**: 서버는 연습 요청(`rehearsal: true`)을 **같은 계산으로 처리하되 트랜잭션을 되돌린다** → 사건·대안·영업 확인·선택이 실제 여행에 남지 않음. 테스트: 연습 전후 DB가 같음(모든 표), 같은 시각·위치면 연습과 실제의 응답이 같음 |
| C4 | 연습 중 [대안 고르기]·[영업 확인했어] 같은 행동은 **화면에서만** 반영되고 "연습이라 저장하지 않았어" 한 줄(§D4). 실제 일정은 바뀌지 않음 (원칙 3 "일정 변경은 사용자가 고른 뒤"를 연습이 어기지 않게) |
| C5 | 영업시간은 그 **요일**의 값으로(Google 값은 요일별). 날짜가 먼 미래여도 같음. 출처·확인 상태 표시는 실제와 같게 |
| C6 | 연습 모드에서는 실제 위치를 읽지 않음 (A3 멈춤) |

## 8. 하지 말 것
- 백그라운드 위치 요청, 위치 저장(DB·기기·로그), 쿼리에 위치
- 연습 결과를 실제 여행에 쓰기
- 키 값 출력·`.env` 읽기, 클라우드 Supabase에 테스트 데이터, 8000 서버 사용(점검은 8010 + 로컬)
- `docs/` 수정, 저장소 밖 검색, 이름으로 프로세스 끄기, main에 바로 커밋, 자동 설치 명령을 묻지 않고 실행

## 포트폴리오 포인트
- 위치를 "필요한 순간, 앱을 쓰는 동안, 저장 없이"로 좁히고, **로그·DB·기기 어디에도 좌표가 남지 않는 것을 테스트로 고정**
- 연습 모드를 별도 로직이 아니라 **같은 계산 + 트랜잭션 되돌리기**로 만들어, 연습과 실제가 어긋나지 않게 함

| 예상 면접 질문 | 답 |
|---|---|
| "위치 정보는 어떻게 다뤘나요?" | 여행 당일 그 화면을 쓸 때만 '앱 사용 중' 권한으로 받고, 요청 본문으로만 보내 서버 로그에 남지 않게 했습니다. DB·로그·기기에 좌표가 없는지 테스트로 확인하고, 거절해도 시계만으로 동작합니다 |
| "미리 보기 기능은 어떻게 실제와 같게 했나요?" | 따로 만들지 않고 실제와 같은 계산을 돌린 뒤 트랜잭션을 되돌렸습니다. 연습 전후 DB가 같고, 같은 입력이면 연습과 실제의 응답이 같은지 테스트로 고정했습니다 |
