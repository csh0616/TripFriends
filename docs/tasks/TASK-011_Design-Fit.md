## 9. 질문 답 (11-09, test-writer Q1~Q14)
### 범위 변경: 서버 작은 변경 허용
날짜 목록이 날마다 코스를 따로 부르지 않게, **서버가 날 요약을 같이 준다** (§8의 "서버 변경 없음"을 이 범위만 바꿈). 순서: test-writer(서버 테스트 추가) → **backend** → frontend

| Q | 답 |
|---|---|
| 1 [새 여행 만들기] | **§4-11 표 `btn-new-trip`**(bg-2 · 높이 52 · 너비 화면 − 40 · 15/22·600). "글자 버튼" 줄은 TASK-010 임시 모양이라 폐기 (PM이 DESIGN-001 고침) |
| 2 요약·꼭 갈 곳 | **서버가 `GET /trips/current`의 날마다 함께 준다**: `summary {end_time, place_count, move_min}`(고른 코스가 있을 때), `must_visits [{place_id, name}]`. 요약 글은 **"18:30 끝 · 8곳 · 이동 125분"** (걷기 km는 데이터가 없어 쓰지 않음). 앱은 코스를 따로 부르지 않는다 |
| 3 카드 안 [알아서 짜 줘] | 누르면 **바로 자동 계획**(FR-05) → 코스안 화면. 오늘인데 코스가 없는 카드도 계획 전과 같이 [같이 고르기]·[알아서 짜 줘] 둘 다 |
| 4 [오늘 여행 보기] 밑 줄 | [같이 고르기]와 같은 모양: **"1일째 · 12/11 금"** |
| 5 머리 | ● = 날 순서대로 한 자리씩, **그날 고른 코스가 있으면 채움**(오늘·지난 날 포함). "N일 계획 완료" = 고른 코스가 있는 날 수(오늘·지난 날 포함). 오른쪽 말: 여행 전 "D-35", 여행 중 "여행 중", 끝난 뒤 **"여행 끝"**(§10). 하루 여행 제목 **"오사카 당일 여행"**, 끝난 뒤 제목은 그대로 |
| 6 N일째 | 서버 날 번호(1부터) 맞음 |
| 7 두 구간 | **"11:00–14:00 · 17:00–22:00"** (가운데 점) |
| 8 "–" 범위 | **앱 전체**: 시각 범위를 보여 주는 곳은 모두 `timeRange`(고정 일정, 여행 중 카드 포함). 바뀌는 기존 테스트는 승인 |
